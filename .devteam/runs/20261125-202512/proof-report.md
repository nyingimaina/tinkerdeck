## Assumptions

Decided on the builder's behalf (change any that are wrong):

- One local person uses the app on their own machine; there are no accounts, roles, sharing or per-record permissions, so every user can reach every control and nothing needs authorisation.
- The remembered layout is stored in the window's existing local preference store, as the sidebar's collapsed state already is, not in a new Rust command or config file; it holds only layout flags (and known app ids if any per-app field is kept), so no backend, permission or CSP change is needed.
- Only the sidebar's expanded/collapsed state is restored across sessions. Because the earlier promise 20261125-153618:R5 must still hold, the git tools, git drawer and console always start hidden when an app is opened, and a previous session's open drawer or console is never reopened.
- The command palette lists app-level commands (the global ones and those that exist only while an app is open), not view-local value pickers, data navigation, context dialog answers or the editor's own file commands, which stay on their always-visible controls.
- A console in an app with no terminals is the only workspace; its Hide console control stays visible but disabled with a reason, and Reset layout leaves it on screen rather than showing a blank app view.
- Reset layout is a palette command with no shortcut; it touches only the sidebar, git tools, git drawer and a hideable console. Dialogs, banners, the branch menu, the theme finder and the app edit form are not closed by Reset layout, are not remembered between sessions, and keep their existing close and dismiss controls.
- Hidden consoles keep running and keep their output for the current session, but terminal processes and old output are not restarted or restored after the app closes.
- The app remains a desktop window with its current minimum size; no phone layout is added.
- The advanced top-bar controls, groups and command names stay as revision 1's agreed plan; this revision does not redesign them.
- Packages are chosen only after the plan confirms a free, open licence, active maintenance and React 18.3 plus Tauri-webview compatibility. Menus, dialogs and the hide/collapse controls may stay in-house with the reason recorded; a published jattac package whose files are incomplete is recorded and replaced rather than forced in.

## Out of scope

- Redesigning screens, views, panels, dialogs or navigation flow, or moving the editor into the app view; the editor stays a separate full view.
- Changing what existing functions do: only where they live, how they are grouped, whether they show by default, how they are hidden, what is remembered and which shortcuts reach them.
- Adding hide controls to banners, dialogs or terminal panes, or changing how their existing close and dismiss controls behave; they keep their current behaviour.
- Moving the Shell or Theme controls behind a dialog.
- Backend, data-storage, permission, CSP or config-format changes; the layout uses the window's existing local preference store.
- Restoring terminal processes, console shells or old terminal output across a restart; only layout choices are remembered.
- Reopening dialogs, banners, the branch menu, the theme finder or the app edit form with stale content after a restart.
- Adding a phone layout; the window keeps its existing desktop minimum size.

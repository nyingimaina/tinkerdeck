## Assumptions

Decided on the builder's behalf (change any that are wrong):

- One local person uses Tinkerdeck on their own Windows machine; there are no accounts, roles, sharing or per-file permissions to add.
- The existing loading, empty, error and too-large states and wording are kept; the global view shows an empty message when no unowned file is open, and the workspace tab strip scrolls when it overflows.
- A workspace or the global view keeps every editor tab it has for the session; the planning target is 50 open editor tabs per workspace and 20 workspaces, and files remain whole-file reads under the existing 5 MB edit cap.
- When two workspace roots are equally deep, the workspace that appears first in the saved workspace list owns the file.
- When Ctrl+O returns several files with different owners, every chosen file opens in its own strip; the main area ends on the owner of the last chosen file, and the other files stay open in their own strips.
- The per-workspace selected tab is remembered for the session only; this revision does not add restart persistence for it.
- Only the vertical 'Open editors' side pane is removed; every other screen, panel, dialog, the footer and the separate editor view stay as they are.
- This revision adds no new dependency, IPC command, permission or stored field; the context menu, rename, configuration migration and tdk/MCP changes are later revisions.

## Out of scope

- Split views showing an editor beside a terminal.
- Dragging tabs between workspaces or between a workspace and the global view.
- Chunked or streamed file loading and a read-only large-file viewer; files stay whole-file reads under the existing 5 MB edit cap.
- Saving an 'Open terminal here' Console as a permanent workspace terminal.
- Terminals in the global editor view.
- The rest of the overall request, delivered in later revisions: the explorer right-click menu, the App/Project to Workspace rename, the configuration version 2 migration, the tdk/MCP rename, the editor action bar and shortcut scoping, unsaved-document home workspace, tab movement on ownership change, and the Reveal in File Explorer command.

## Role documentation

### Analyst: requirements

This is revision 1 of 3 of the larger workspace-editor feature and covers R1 to R5 only. A file that belongs to a registered workspace opens as an editor tab in that workspace's own tab strip beside its terminal and Console tabs; the main area switches to the owning workspace when needed and never to the global editor view. Files that belong to no workspace stay in a separate global editor view whose strip lists only those unowned files, so one file is never shown in two strips. Ownership is by path with the deepest root winning, and each workspace has one selected tab that can be a terminal, Console or editor tab. Inside a workspace the editor has no vertical 'Open editors' side pane, while the global view shows a plain ungrouped list. The single CodeSurface is loaded lazily on first use and reused for whichever editor tab is visible. For workspace-owned files this revision deliberately replaces the earlier accepted Open file requirement, and for the side pane it deliberately replaces the earlier accepted tidy-up requirement; the remaining parts of the overall request (explorer context menu, App/Project to Workspace rename, configuration version 2 migration, tdk/MCP rename and the other later items) are delivered in later revisions. The existing old window files that own the main view and the editor's active document are expected to change, but only after characterization tests freeze today's behaviour.

### Architect: design

This revision builds R1-R5 only. It reuses src/state/editorGroups.ts unchanged: ownerOf already returns the deepest registered workspace root that contains a path (first workspace wins a depth tie) and groupTabs already files unowned and unsaved tabs last under Misc. A new pure helper, src/state/workspaceTabs.ts, turns the existing groupTabs result into a per-workspace editor lookup plus the unowned list and resolves a workspace's one selected tab (a valid editor id wins, otherwise the Console group when a console instance is selected, otherwise the selected terminal). Because both strips are derived from that one partition, an editor can only be in one strip, and save-as, rename, move, root change or workspace removal re-files it on the next render with the same document id, so content, dirty state and CodeMirror undo survive without a copy (R3, R4). App keeps a session-only selected editor tab id per workspace beside L.selectedTerminalId; selecting a terminal or Console clears it, selecting an editor tab hides the terminal area but leaves it mounted, and opening a file from the explorer, Ctrl+O, a pending command-line file or tdk switches to the owning workspace, selects the file's tab and never enters the global view (R1). useEditor now reports the opened tab's id and path through onOpened; App defers that route until the saved workspaces are loaded, then sends a workspace-owned file to its workspace and an unowned file to the header's global editor view (R1, R2, A3). A new pane-less EditorSurface holds the existing lazy CodeSurface, the Raw/Preview toggle, Save and Save as, the file error and the language/EOL/encoding status bar. It is mounted once at App level, shown for the selected editor tab in either the workspace main area or the global view, and only hidden (never unmounted) while a terminal tab is selected, so one CodeMirror instance is reused and no terminal remounts (R1, R2, R5, A1). EditorView keeps the separate global view with its New/Open/Bin toolbar, error and bin, and delegates the editor body (Save, Save as, Raw/Preview and the status bar) to the shared surface shown in that same view; it now renders a flat ungrouped ZestTabs strip of unowned tabs with dirty mark and close and a clear empty message, and the grouped vertical 'Open editors' pane is the only panel removed (R2, R5). Every other screen, panel, dialog, footer and the separate editor view stay present. TabStrip keeps its existing ZestTabs list and gains editor tabs beside the terminals and Console with one selected value, dirty mark and close; the terminal Start/Stop/Restart buttons stay and are disabled while an editor tab is selected. The global window Ctrl+S/N/O/W listener stays in EditorView unchanged; shortcut scoping, the strip editor action bar, the workspace rename, config v2, the context menu and the tdk/MCP rename are later revisions. Old window files (App.tsx, App.module.css, useEditor.ts, EditorView.tsx/css, TabStrip.tsx/css) change only where R1/R5 cannot be reached from new code, as R1's acceptance permits: each change is a small adapter (route/selection in App, an additive onOpened payload and memoised tabs in useEditor, the body delegated to EditorSurface from EditorView, extra editor items in TabStrip) and each is frozen first by the characterization tests named in scope and run on today's code before any edit. The new pure helper lives beside the editor state under src/state, which R1's acceptance allows because it only extends that state and has its own tests. No Rust, src/api, IPC command, capability, CSP, dependency, permission or saved field is added. Scale and cost: the partition is memoised on [tabs, apps] and is O(open tabs x workspaces) once per change (50 x 20) with no disk scan and no polling; ZestTabs already scrolls and arrow-navigates overflow; CodeMirror still draws only visible lines from the existing 5 MB whole-file cap; only one surface is alive and closing a tab drops its state through liveIds; startup is unchanged because CodeMirror is still only fetched once an editor tab is first shown, and there is no new network, storage or memory growth beyond the session selection map.

## Assumptions

Decided on the builder's behalf (change any that are wrong):

- users: There is one local desktop user with the operating system's own access rights; the home, app and editor views are context, not user roles or permissions.
- data: This revision adds no new persisted fields. The explorer root is derived from the current view and active tab, and expanded folders and scroll position are kept only for the session. Moving dialogs to side panes adds no stored data, and every dialog keeps its current content and actions. The per-terminal executable field lands in revision 3 (R11).
- validation: An unreadable folder shows as locked rather than raising an error; a missing or removed path is reported without breaking the tree; F5 in the home and editor views is a no-op; a failed side-pane package check is reported and R8 stops.
- states: An empty folder shows an empty state; a locked or unreadable folder shows a locked state; listing shows a loading state; the drive list is the top state; every dialog keeps its current open, content and close states, only presented in a side pane; F5 shows no separate state but mirrors the Start all / Stop all button, including while a start or stop is in progress.
- duplicates: Pressing F5 twice quickly must not start a terminal twice or leave the app half-started; changing the explorer root must not create or duplicate tabs.
- volume: The explorer loads one folder level at a time and hides node_modules, .git, target and dist by default behind a Show hidden control, so a folder with a few thousand entries stays responsive; the drive list is obtained without scanning drive contents.
- privacy: No data leaves the machine; the explorer can browse any path the operating system allows, including a misc file's parent folder, and no additional hiding of dotfiles is added beyond the agreed build/VCS hide list.
- quality: Explorer listing reads only the requested level and stays responsive on large folders; the tree and side panes are keyboard-usable with visible focus and a named close control; the side panes fit a 360px-wide window; the package is verified to install and ship CSS before use.
- R6 supersedes the earlier accepted requirement 20261125-153618:R4 that promised F5 refreshes. The old F5-refresh behaviour, the F5 shortcut entry, every menu/palette/help hint advertising F5 as refresh, and the tests asserting F5 refreshes are replaced by R6. Refresh remains available from its on-screen buttons and the palette entry, with no keyboard shortcut (R12 in revision 3 formalises the shortcut removal).
- R8 supersedes the earlier accepted requirement 20261125-153618:R2 only in its promise that no existing dialog is redesigned or replaced: every dialog (and the branch menu) moves from a centred modal to a responsive side pane. R2's promise that every existing screen, panel, dialog and the footer remains present still holds, and each dialog keeps its current content, fields, buttons, actions and close paths; only the presentation changes.
- The user's home folder is the explorer root whenever no app root and no file path apply, and the drive list is reachable by going Up; this is the assistant's proposed default and the builder did not object.
- Expanded-folder and scroll state is kept only for the session and is not required to survive a restart.
- F5 is swallowed in the home and editor views so it cannot reload the webview or act on a remembered selected app.
- The theme finder's width fix is delivered on its own even though R8 later moves it into a side pane, so the overflow is fixed regardless of R8's outcome.
- The exact jattac responsive-layout package is the approved one recorded by the design; if its published build does not install cleanly or ship its CSS, R8 is stopped and reported while R13, R6 and R7 still ship.

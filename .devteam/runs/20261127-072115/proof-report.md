## Assumptions

Decided on the builder's behalf (change any that are wrong):

- One local user on their own Windows machine; there are no accounts, roles or sharing.
- The sidebar opens on Projects every time the app starts; the chosen tab is remembered only for the running session, because the earlier accepted promise keeps td.sidebarCollapsed as the only saved sidebar layout value.
- Typical use is a handful of apps and terminals, but the sidebar must still stay responsive with hundreds of apps and thousands of terminals.
- The explorer's existing loading, empty-folder, drive-list, no-root and error states and wording are kept unchanged; only the header gains the context name.
- The exact Projects and Files icon glyphs and tab styling follow the existing rail and sidebar styles from revision 1.

## Out of scope

- A split layout (Projects on top, Files below) with a draggable or resizable divider.
- Changing which root folder the file-system explorer shows; the root rules stay as they are.
- Adding, renaming, moving or deleting files from the sidebar.
- Switching tabs automatically when an app, terminal, Home or file is selected.
- Redesigning the apps-and-terminals list itself.
- Persisting the active tab across restarts or adding any new localStorage layout key; td.sidebarCollapsed stays the only saved sidebar layout value.
- Any new Tauri permission, backend command, file location or network access.

The left sidebar of Tinkerdeck gains two tabs: Projects keeps what the sidebar shows today (the Home row and each app with its terminals), and Files shows the existing file-system explorer filling the panel, so users no longer scroll past every app to reach it. The Files header now names the context whose folder is shown (the app's name, 'Misc' or 'Home') as well as the folder, the Projects tab label carries one roll-up status dot so overall status stays visible while Files is open, the sidebar opens on Projects each time and remembers the chosen tab only for the running session (no new saved layout value, because td.sidebarCollapsed remains the only saved sidebar layout value), and Ctrl+Shift+E jumps to Files. The explorer's root rules, file operations and the apps/terminals list are unchanged.

### Architect: design

This revision finishes the two-tab sidebar that revision 1 already renders; it does not move the sidebar or replace its structure. The active tab moves from Sidebar-local state into App state so one place can set it for a tab click, a rail icon or the new Ctrl+Shift+E shortcut, and so the Files panel can be told whether it is visible. Per the decided R8 the tab is kept for the running session only: App initialises it to 'projects', never reads or writes a tab key, and localStorage still holds only 'td.sidebarCollapsed'. Sidebar takes an optional tab/onTabChange pair and falls back to its existing local state, so its standalone tests and the rail keep working unchanged; the Files panel stays mounted after first use, so tab switches keep the folder, expanded levels and the explorer cache. App already resolves the explorer root (root, appId, source) and builds the ExplorerPanel element it passes to Sidebar, so it derives the Files header context there (the owning app's name, 'Misc' or 'Home') and passes it plus an active flag straight into that element; root.ts and its selection rules are not touched, and ExplorerPanel only adds the context to the header and saves/restores the .body scrollTop across a hide/show. R7 adds one memoised projectsRollup() in SidebarProjects.tsx that reuses rollup()/isExecutable over every app's executable terminals, exactly as appRollup() already does per app; Sidebar renders it once on the Projects tab label and once on the rail Projects icon (wrapped aria-hidden so the tab and button names stay exactly 'Projects'/'Files' and the existing role=img counts do not change). R9 adds a 'showFiles' entry to the one shared shortcut registry (id, 'Show Files', Ctrl+Shift+E, matchShortcut case), an App palette action and keydown case, and a Help line that reads its keys from the same registry; TerminalHost needs no code change because it already forwards every isAppShortcut key. Scale and resource cost stay bounded: the tab switch is an O(1) hidden toggle with the memoised 500-row Projects list untouched and no explorer re-listing (resetKey excludes the tab); the roll-up is one O(executable terminals) pass recomputed only when apps or terminal state change, never on a tab switch; the context is a small memoised apps lookup; scroll save/restore is O(1); the explorer's cached levels remain capped by MAX_CACHED_LEVELS; and there are no new files, commands, Tauri permissions, CSP rules, polling, network calls or dependencies.
